Build a full-stack, password-protected internal web application called "Permionics BD Suite" — 
a proprietary business development dashboard for Permionics Membranes Pvt. Ltd. It should feel 
like real enterprise software: polished, fast, confident, not like a student project or a generic 
admin template.

=== BRAND / DESIGN SYSTEM ===
- Primary color: deep blue #0C4A8C
- Secondary/accent: a lighter steel blue (#3B7DC4) and a clean white (#FFFFFF) / light grey (#F5F7FA) background
- Font: Inter (all weights) for everything — headings, body, labels, buttons
- Aesthetic reference: DuPont / Pall / Koch membrane industry sites, or Adani/Reliance corporate 
  dashboards. Enterprise, engineering-grade, no playful colors, no gradients unless very subtle.
- Use a proper sidebar navigation layout (logo top-left, nav items with icons, collapsible on mobile)
- Use lucide-react icons throughout, consistent sizing
- Include a placeholder Permionics logo mark (stylized membrane/filter icon — concentric layered 
  arcs or a droplet-through-membrane motif in the brand blue) in the sidebar header and login page
- Cards should have soft shadows, 8-12px radius, generous whitespace, clear section headers
- Data tables should be clean with subtle zebra striping, sortable headers
- Include subtle SVG vector illustrations on the login page and empty states (industrial/membrane 
  themed — pipes, filtration schematic line art in brand blue, low-opacity)
- Dark mode is not required, keep it light/enterprise

=== AUTH ===
- Simple password-protected login (single shared team password is fine, stored as env var 
  ADMIN_PASSWORD, hashed comparison) — this is an internal tool, not public-facing
- Store session in a secure httpOnly cookie / JWT after login
- Login page: centered card, Permionics logo, password field, "Access BD Suite" button, 
  subtle vector background
- Add a basic "Remember me" and a logout button in the sidebar footer

=== APP STRUCTURE (sidebar nav items) ===
1. Dashboard (home/overview)
2. Case Study Library
3. Case Study Generator
4. Questionnaire Builder
5. BD Assistant (chatbot)
6. Settings

=== 1. DASHBOARD ===
- Overview cards: total case studies in library, questionnaires created, sectors covered, 
  last updated date
- Recent activity feed (last 5 case studies/questionnaires created)
- Quick action buttons: "New Case Study", "New Questionnaire", "Ask BD Assistant"

=== 2. CASE STUDY LIBRARY (this is the shared database) ===
- This is the persistent store that both the generator AND the chatbot read from
- Table/grid view of all case studies with: client name, sector (Pharma/Herbal, Textile, 
  CETP/Municipal, Food & Beverage), technology used (UF/RO/NF/MBR etc.), summary, date added
- Each case study is a structured record with fields: client_name, sector, location, 
  challenge, solution, technology_stack, capacity (e.g. m3/day), results/ROI, testimonial 
  (optional), tags (array), full_text (long-form narrative used for chatbot retrieval)
- Filters by sector and technology
- Click into a case study for full detail view (styled like a print-ready one-pager, 
  DuPont-inspired layout — header with client name/sector, challenge/solution/results 
  sections, key metrics as stat cards)
- "Add New Case Study" form that saves directly into this database (this is how the 
  library grows over time — this is the critical requirement, it must be persistent 
  and growable, not hardcoded)
- Include seed data for these real cases so the demo isn't empty: Waaree Energies, 
  Nandesari CETP, Hyderabad CETP, a generic Pharma/Herbal client — write plausible 
  placeholder details for each (client, challenge, solution, results) since I'll 
  edit them with real data after

=== 3. CASE STUDY GENERATOR ===
- Form-based tool: user fills in client name, sector, challenge, solution, technology, 
  capacity, results
- Generates a styled, print-ready HTML case study output (same DuPont-inspired visual 
  format as the library detail view) with a "Save to Library" button that pushes the 
  generated case study directly into the Case Study Library database
- Also include "Export as PDF" and "Copy shareable link" buttons
- Live preview pane next to the form (split screen: form left, rendered preview right)

=== 4. QUESTIONNAIRE BUILDER ===
- Sector-tabbed questionnaire tool: Pharma/Herbal, Textile, CETP/Municipal, Food & Beverage
- Each tab has a pre-built set of relevant technical discovery questions (water source, 
  flow rate, TDS/BOD/COD levels, current treatment method, budget range, timeline, 
  compliance requirements etc.) — write realistic sector-specific questions for each tab
- Allow adding custom questions per sector
- "Generate Client Questionnaire" produces a clean styled PDF/HTML form that can be sent 
  to a prospective client
- Save completed/sent questionnaires to a list with client name + date + sector for tracking

=== 5. BD ASSISTANT (RAG CHATBOT) — the key new feature ===
- A chat interface (right-docked panel or full page) where BD team members can ask questions like:
  "Have we done a CETP project with capacity above 500 KLD?"
  "What results did we get for the Waaree Energies project?"
  "Give me a pitch angle for a textile client worried about ZLD compliance"
  "What's our standard approach for pharma effluent treatment?"
- This MUST answer using ONLY the case studies stored in the Case Study Library database — 
  implement this as retrieval-augmented generation:
  1. When a case study is added/edited, store its full_text in the database
  2. On each chat query, retrieve the most relevant case study records (simple keyword/
     tag matching is fine for MVP — sector match, technology match, text search across 
     full_text — vector embeddings are a nice-to-have if easy but not required)
  3. Construct a prompt that includes the retrieved case study text as context, plus the 
     user's question, and send it to the Anthropic API (model: claude-sonnet-4-6) via a 
     backend route — NEVER expose the API key to the frontend, call it from a server-side 
     route only
  4. Stream or return the answer, and show which case study/studies it drew from as 
     citations/source chips below the answer (e.g. "Source: Waaree Energies — RO Case Study")
  5. If no relevant case study is found, the assistant should say so honestly rather than 
     making something up, and suggest adding a new case study for that scenario
- Include a chat history for the session (doesn't need to persist across logins, session-only is fine)
- Give the assistant a system prompt establishing it as "Permionics BD Assistant" — helpful, 
  precise, cites its sources, never fabricates technical specs not present in the case studies

=== TECH STACK ===
- React frontend (Vite), Tailwind CSS for styling
- Node/Express backend (or Next.js if you prefer a unified structure — your choice, 
  pick whichever lets you ship fastest and most reliably)
- Supabase as the database (Postgres) — set up tables for: case_studies, questionnaires, 
  chat_sessions (optional). Use Supabase client on the backend only, not exposed to frontend 
  with elevated permissions
- Environment variables needed: ADMIN_PASSWORD, ANTHROPIC_API_KEY, SUPABASE_URL, SUPABASE_SERVICE_KEY
  — set these up as Replit Secrets, do not hardcode them anywhere
- Structure the repo cleanly: /client (frontend), /server (backend/api routes), 
  README.md explaining setup

- Must look and feel like real internal enterprise software, not a hackathon demo
